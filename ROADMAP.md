Current integration finding: plugin storage is shared globally; native plugin session context does not expose inbox/form APIs. Location- and server-qualified keys plus a trusted, verified same-server bridge are required before automatic scheduling is enabled. Generic defaults remain fail-closed; bookkeeping does not require this bridge.

Native acceptance found two differences from current online documentation: the pinned directory loader needs a root `index.ts` shim, and successful execution emits a terminal event rather than `session.idle`. Both corrections passed against the actual 2.0.25 host, including explicit create/resume commands and watched-config reload. Live acceptance additionally requires process-local server identity to be verified before claiming its location/server lock; another process sharing global configuration must not acquire that server's ownership.

Earlier example-project follow-up is superseded by observed normal watcher convergence in docs/budget-verification.md. No lifecycle intervention was authorized or performed.
